## 1. Server Requirements

| Requirement | Minimum | Recommended |
|---|---|---|
| PHP | 8.2 | 8.3 |
| PHP extensions | BCMath, Ctype, cURL, DOM, Fileinfo, JSON, Mbstring, OpenSSL, PCRE, PDO, PDO_MySQL, Tokenizer, XML | same |
| Node.js | 22.12+ | latest LTS |
| Composer | 2.x | latest |
| Database | MySQL 8.0 / MariaDB 10.6 / PostgreSQL 14 | MySQL 8.0 |
| Redis | 6+ (for queues, cache, sessions, and Reverb scaling) | 7 |
| Web server | Nginx 1.18+ | Nginx latest |
| OS | Ubuntu 22.04 LTS | Ubuntu 24.04 LTS |
| RAM | 1 GB | 2 GB+ |
| Storage | 10 GB | 20 GB+ (for uploaded logos, avatars, sermon files) |

> **Note:** SQLite is fine for local development but is **not supported in production**. Use MySQL or PostgreSQL.

## 2. First-Time Server Setup

```bash
# Install system packages (Ubuntu/Debian)
sudo apt update && sudo apt upgrade -y
sudo apt install -y nginx mysql-server redis-server supervisor certbot python3-certbot-nginx \
    php8.3-fpm php8.3-cli php8.3-mysql php8.3-mbstring php8.3-xml php8.3-curl \
    php8.3-bcmath php8.3-zip php8.3-redis php8.3-gd php8.3-intl unzip

# Install Composer
curl -sS https://getcomposer.org/installer | php
sudo mv composer.phar /usr/local/bin/composer

# Install Node.js 22.x
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs

# Confirm versions
php --version    # PHP 8.3.x
composer --version
node --version   # v22.12+
mysql --version
```

### MySQL database setup

```sql
-- Run as root: sudo mysql
CREATE DATABASE church_platform CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'church_user'@'localhost' IDENTIFIED BY 'YOUR_STRONG_PASSWORD';
GRANT ALL PRIVILEGES ON church_platform.* TO 'church_user'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

## 3. Environment Variables

Create `/var/www/church-platform/.env` (never commit this file).

```dotenv
# ─── App ──────────────────────────────────────────────────────────────────────
APP_NAME="Church Platform"
APP_ENV=production
APP_KEY=                          # generated by: php artisan key:generate
APP_DEBUG=false
APP_URL=https://your-domain.com
APP_LOCALE=en

# ─── Logging ──────────────────────────────────────────────────────────────────
LOG_CHANNEL=stack
LOG_STACK=daily
LOG_LEVEL=warning                 # production: warning or error (not debug)

# ─── Database — MySQL ─────────────────────────────────────────────────────────
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=church_platform
DB_USERNAME=church_user
DB_PASSWORD=YOUR_STRONG_PASSWORD

# ─── Cache / Session / Queue ──────────────────────────────────────────────────
# Redis is strongly recommended for production.
# With Redis: all three use the same connection, zero DB table overhead.
CACHE_STORE=redis
SESSION_DRIVER=redis
SESSION_LIFETIME=120
QUEUE_CONNECTION=redis            # switch from 'sync' (dev) to 'redis' (prod)

# ─── Redis ────────────────────────────────────────────────────────────────────
REDIS_CLIENT=phpredis
REDIS_HOST=127.0.0.1
REDIS_PASSWORD=null               # set if Redis has a password
REDIS_PORT=6379

# ─── Mail ─────────────────────────────────────────────────────────────────────
# Option A: Mailgun
MAIL_MAILER=mailgun
MAILGUN_DOMAIN=mg.your-domain.com
MAILGUN_SECRET=key-xxxxxxxxxxxx
MAIL_FROM_ADDRESS=noreply@your-domain.com
MAIL_FROM_NAME="Grace Community Church"

# Option B: SMTP (Gmail, SendGrid, etc.)
# MAIL_MAILER=smtp
# MAIL_HOST=smtp.sendgrid.net
# MAIL_PORT=587
# MAIL_USERNAME=apikey
# MAIL_PASSWORD=SG.xxxxxxxxxxxx
# MAIL_ENCRYPTION=tls
# MAIL_FROM_ADDRESS=noreply@your-domain.com
# MAIL_FROM_NAME="Grace Community Church"

# ─── Broadcasting — Reverb (real-time notifications) ──────────────────────────
BROADCAST_CONNECTION=reverb
REVERB_APP_ID=your-reverb-app-id            # generate: php artisan reverb:install (already done)
REVERB_APP_KEY=your-reverb-app-key          # OR pick any random 32-char string
REVERB_APP_SECRET=your-reverb-app-secret    # OR pick any random 64-char string
REVERB_HOST=your-domain.com                 # the domain Reverb will be proxied at
REVERB_PORT=443
REVERB_SCHEME=https
REVERB_SERVER_HOST=0.0.0.0
REVERB_SERVER_PORT=8080                     # internal port (Nginx proxies 443 → 8080)

# Vite needs to know where the Reverb WS is during build
VITE_REVERB_APP_KEY="${REVERB_APP_KEY}"
VITE_REVERB_HOST="${REVERB_HOST}"
VITE_REVERB_PORT="${REVERB_PORT}"
VITE_REVERB_SCHEME="${REVERB_SCHEME}"

# ─── Filesystem ──────────────────────────────────────────────────────────────
FILESYSTEM_DISK=local             # uploaded files stay on the server in storage/

# ─── YouTube Sync ─────────────────────────────────────────────────────────────
YOUTUBE_API_KEY=AIzaSy...         # Google Cloud Console → YouTube Data API v3

# ─── Church Defaults (used before admin configures via Settings) ───────────────
CHURCH_NAME="Grace Community Church"
CHURCH_TAGLINE="A Place to Belong"
CHURCH_EMAIL=hello@your-domain.com
CHURCH_PHONE="+1 (555) 000-0000"
CHURCH_ADDRESS="123 Faith Avenue, Your City, ST 00000"
CHURCH_FACEBOOK=
CHURCH_INSTAGRAM=
CHURCH_YOUTUBE=
CHURCH_TWITTER=
```

> **Key difference from dev:** `QUEUE_CONNECTION` changes from `sync` → `redis` and `BROADCAST_CONNECTION` changes from `log` → `reverb`. Both need the Supervisor processes below to actually process jobs and handle WebSocket connections.

## 4. First Deployment Steps

Run these commands once on the server after uploading the code for the first time.

```bash
# ── 1. Navigate to project directory
cd /var/www/church-platform

# ── 2. Install PHP dependencies (no dev packages in prod)
composer install --no-dev --optimize-autoloader

# ── 3. Install Node.js dependencies and build frontend assets
npm ci
npm run build

# ── 4. Generate the application key (REQUIRED — once per install)
php artisan key:generate

# ── 5. Run database migrations
php artisan migrate --force

# ── 6. Seed roles and permissions (REQUIRED on any fresh DB)
#    This is idempotent — safe to re-run on existing DBs too.
php artisan db:seed --class=RolesAndPermissionsSeeder

# ── 7. Create the public storage symlink (for logo and avatar uploads)
php artisan storage:link

# ── 8. Cache config, routes, and views for production speed
php artisan config:cache
php artisan route:cache
php artisan view:cache

# ── 9. Set correct file permissions
sudo chown -R www-data:www-data /var/www/church-platform
sudo chmod -R 755 /var/www/church-platform
sudo chmod -R 775 /var/www/church-platform/storage
sudo chmod -R 775 /var/www/church-platform/bootstrap/cache
```

## 5. Nginx Configuration

Create `/etc/nginx/sites-available/church-platform`:

```nginx
server {
    listen 80;
    server_name your-domain.com www.your-domain.com;
    # Certbot will add the HTTPS redirect here automatically
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name your-domain.com www.your-domain.com;

    root /var/www/church-platform/public;
    index index.php;

    # ── SSL (Certbot will fill these in) ───────────────────────────────────────
    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;
    include             /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam         /etc/letsencrypt/ssl-dhparams.pem;

    # ── Security headers ───────────────────────────────────────────────────────
    add_header X-Content-Type-Options nosniff;
    add_header X-Frame-Options SAMEORIGIN;
    add_header X-XSS-Protection "1; mode=block";
    add_header Referrer-Policy strict-origin-when-cross-origin;

    # ── Reverb WebSocket proxy (wss://your-domain.com/app/...) ────────────────
    location /app/ {
        proxy_pass             http://127.0.0.1:8080;
        proxy_http_version     1.1;
        proxy_set_header       Upgrade $http_upgrade;
        proxy_set_header       Connection "Upgrade";
        proxy_set_header       Host $host;
        proxy_set_header       X-Real-IP $remote_addr;
        proxy_set_header       X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header       X-Forwarded-Proto $scheme;
        proxy_read_timeout     60;
        proxy_connect_timeout  60;
        proxy_send_timeout     60;
    }

    # ── Laravel / Inertia ─────────────────────────────────────────────────────
    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass   unix:/var/run/php/php8.3-fpm.sock;
        fastcgi_index  index.php;
        fastcgi_param  SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include        fastcgi_params;
        fastcgi_read_timeout 300;
    }

    # ── Static asset caching ───────────────────────────────────────────────────
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|ico|webp|woff|woff2|ttf|eot)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    location = /favicon.ico { log_not_found off; access_log off; }
    location = /robots.txt  { log_not_found off; access_log off; }

    client_max_body_size 10M;   # allow up to 10 MB file uploads
}
```

```bash
# Enable the site
sudo ln -s /etc/nginx/sites-available/church-platform /etc/nginx/sites-enabled/
sudo nginx -t   # verify config
sudo systemctl reload nginx
```

## 7. Supervisor — Queue Worker

The queue worker processes background jobs: email delivery, YouTube sermon sync, and all `SermonPublished` / `VolunteerAssigned` / etc. notifications.

Create `/etc/supervisor/conf.d/church-queue.conf`:

```ini
[program:church-queue]
process_name=%(program_name)s_%(process_num)02d
command=php /var/www/church-platform/artisan queue:work redis --sleep=3 --tries=3 --max-time=3600
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=2
redirect_stderr=true
stdout_logfile=/var/www/church-platform/storage/logs/queue.log
stopwaitsecs=3600
```

> `numprocs=2` runs two worker processes. Increase for higher throughput. `--tries=3` retries a failed job 3 times before marking it as `failed`. `--max-time=3600` recycles each worker after 1 hour to prevent memory leaks.

```bash
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl start church-queue:*
sudo supervisorctl status    # should show both workers as RUNNING
```

**After every code deploy**, restart workers so they pick up new code:

```bash
sudo supervisorctl restart church-queue:*
# Or use the graceful signal (waits for current job to finish):
php /var/www/church-platform/artisan queue:restart
```

## 8. Supervisor — Reverb WebSocket Server

Reverb provides real-time notifications (bell badge updates, immediate notification delivery).

Create `/etc/supervisor/conf.d/church-reverb.conf`:

```ini
[program:church-reverb]
process_name=%(program_name)s
command=php /var/www/church-platform/artisan reverb:start --host=0.0.0.0 --port=8080 --no-interaction
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=1
redirect_stderr=true
stdout_logfile=/var/www/church-platform/storage/logs/reverb.log
stopwaitsecs=10
```

```bash
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl start church-reverb
sudo supervisorctl status    # should show RUNNING
```

**After every code deploy**, restart Reverb:

```bash
sudo supervisorctl restart church-reverb
```

## 9. Subsequent Deployments

Use this script for every code update. Save it as `deploy.sh` in the project root (do not commit `.env` or `deploy.sh` itself if it contains secrets):

```bash
#!/usr/bin/env bash
set -euo pipefail

PROJECT=/var/www/church-platform

echo "→ Pulling latest code..."
git -C "$PROJECT" pull origin main

echo "→ Installing PHP dependencies..."
composer -d "$PROJECT" install --no-dev --optimize-autoloader

echo "→ Installing Node dependencies and building assets..."
cd "$PROJECT"
npm ci
npm run build

echo "→ Running migrations..."
php "$PROJECT/artisan" migrate --force

echo "→ Clearing and re-caching..."
php "$PROJECT/artisan" config:cache
php "$PROJECT/artisan" route:cache
php "$PROJECT/artisan" view:cache
php "$PROJECT/artisan" event:cache

echo "→ Restarting queue workers..."
php "$PROJECT/artisan" queue:restart

echo "→ Restarting Reverb..."
supervisorctl restart church-reverb

echo "→ Setting permissions..."
chown -R www-data:www-data "$PROJECT/storage" "$PROJECT/bootstrap/cache"

echo "✓ Deployment complete."
```

```bash
# Run as root or with sudo
sudo bash deploy.sh
```

> **Never** run `npm run build` with `APP_DEBUG=true` pointing at a production DB. Always deploy to staging first.

## 10. Maintenance Mode

```bash
# Take site down (shows resources/views/errors/503.blade.php)
php artisan down

# Restore site
php artisan up
```

To allow specific IPs through during maintenance (e.g., your own IP to verify the deploy):

## 11. Checklist Before Going Live

Run through this before announcing the beta to users:

**Security**
- [ ] `APP_DEBUG=false` in `.env`
- [ ] `APP_ENV=production` in `.env`
- [ ] `APP_KEY` is set (32-char random string)
- [ ] Database password is strong and unique
- [ ] Redis has a password if exposed beyond localhost
- [ ] Nginx security headers are active (`X-Content-Type-Options`, `X-Frame-Options`)
- [ ] SSL certificate installed and HTTP redirects to HTTPS

**Data**
- [ ] `php artisan migrate --force` completed with zero errors
- [ ] `php artisan db:seed --class=RolesAndPermissionsSeeder` run (roles + permissions seeded)
- [ ] Church admin account created (register via `/register` then grant `church_admin` role in DB or Tinker)

**Files**
- [ ] `php artisan storage:link` run — confirms logo/avatar uploads work
- [ ] `storage/` and `bootstrap/cache/` are writable by `www-data`

**Background processes**
- [ ] `supervisorctl status` shows both `church-queue` and `church-reverb` as `RUNNING`
- [ ] Test a queue job: trigger a YouTube sync and verify the notification arrives in the bell

**Mail**
- [ ] Test email delivery via Tinker: `Mail::raw('Test', fn($m) => $m->to('you@example.com')->subject('Test'));`
- [ ] `MAIL_FROM_ADDRESS` is set to a real, SPF-authenticated address

**DNS**
- [ ] `A` record for `your-domain.com` → server IP
- [ ] `A` record for `www.your-domain.com` → server IP (or CNAME → bare domain)

**Environment**
- [ ] `YOUTUBE_API_KEY` is set and the YouTube Data API v3 is enabled in Google Cloud Console
- [ ] `REVERB_APP_KEY` / `REVERB_APP_SECRET` / `REVERB_APP_ID` are consistent between `.env` and the Nginx config
- [ ] `VITE_REVERB_*` variables were set **before** running `npm run build` (they are baked into the JS bundle at build time)

## 12. Troubleshooting

### "Class not found" or "Route not found" after deploy

```bash
php artisan config:clear && php artisan route:clear && php artisan view:clear
composer dump-autoload
php artisan config:cache && php artisan route:cache && php artisan view:cache
```

### Queue jobs not processing

```bash
# Check worker status
sudo supervisorctl status church-queue:*

# Check for failed jobs
php artisan queue:failed

# Retry all failed jobs
php artisan queue:retry all

# View worker log
tail -f storage/logs/queue.log
```

### WebSocket / notifications not working

```bash
# Is Reverb running?
sudo supervisorctl status church-reverb
tail -f storage/logs/reverb.log

# Check VITE_REVERB_* values were correct at build time
cat public/build/manifest.json | grep -i reverb

# Verify Nginx proxy is forwarding /app/ to port 8080
curl -I https://your-domain.com/app/
# Should not return 404; Reverb will respond with a 400 (not a WebSocket upgrade)
```

### Uploads (logos/avatars) return 404

```bash
# Symlink must exist
ls -la public/storage
# If missing:
php artisan storage:link
# Verify the linked directory is writable
ls -la storage/app/public/
```

### "Deactivated" users can log in

This is now blocked at the application level (`AuthService` + `EnsureUserIsActive` middleware). If it still happens, check that `users.is_active` column exists:

```bash
php artisan migrate:status
# Should show: 2026_06_03_000001_add_is_active_to_users_table ... Ran
```

### YouTube sync never completes / "You'll get a notification" but nothing arrives

1. Confirm `QUEUE_CONNECTION=redis` (not `sync`)
2. Confirm `supervisorctl status church-queue:*` shows `RUNNING`
3. Run `php artisan queue:failed` — look for `SyncYouTubeChannelJob`
4. Check `YOUTUBE_API_KEY` is valid and quota is not exhausted (Google Cloud Console → APIs → YouTube Data API v3 → Quotas)

### Checking log output

```bash
tail -f storage/logs/laravel.log    # application log
tail -f storage/logs/queue.log      # queue worker output
tail -f storage/logs/reverb.log     # reverb websocket output
sudo tail -f /var/log/nginx/error.log   # nginx errors
```
